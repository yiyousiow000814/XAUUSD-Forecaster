# News keyset pagination

## Change contract

Replace numbered OFFSET SQL in the existing news-index GET with bidirectional keyset reads, retaining the existing previous/next buttons, page labels, filters, detail expansion, public-copy mapping and exact materialized totals. The current UI has no arbitrary page-jump control. Tokens bind generation, review state, category, page size, target page and the exact persisted published/received/detail-key ordering tuple. Invalid or mismatched tokens fail explicitly; numeric page>1 without a token requests a reset rather than scanning discarded history.

Owner/path: DashboardSync owns existing atomic news activation and complete generation identity; D1 owns immutable accepted facts and the disposable current index; news-index GET owns read-only pagination; AuditView owns navigation and rejects obsolete asynchronous responses. Preview uses the same permitted read-only current D1 news path. No new service, durable cursor table, polling owner, raw-data rewrite, authentication or billing change.

Add two partial expression indexes on active news_index: review/order and review/category/order. The prior generation-index path already has corresponding indexes. Migration is additive and reversible by code reversion without deleting facts. Build/security/required CI and migration preflight precede production publication; apply only the new index migration through Wrangler. Old first-page clients remain compatible; old numeric deep-page requests receive an explicit refresh-required response. Old code can use new indexes, and new code without indexes remains logically correct but is not performance-accepted.

State/recovery: first load and filter changes clear the token; next/previous use server-returned boundary tokens; refreshing a page reuses its input boundary. Generation replacement returns409 and the UI resets once to page1. Invalid input returns400; missing required token returns409. Network failure retains accepted content with an error and retry. Navigation invalidates old requests immediately; component cleanup invalidates in-flight reads. The page SQL returns its observed current generation so a state change between preliminary check and query cannot combine old metadata with new rows. No write transaction or user identity is created by reading. On restart, navigation starts on page1 and uses existing cached first-page data.

Verification: existing D1 contract fixtures cover both index families, all review states, category filters, ties, empty/end pages, full forward/backward traversal, generation changes and malformed/mismatched tokens. Inspect bound actual SQL plans at deep positions, preserving page-size+1 work. Actual route tests and deployed immutable version Preview cover desktop390x844/360x800 navigation, filtering, refresh, expansion and return. Required CI must pass exact head. Production migration/index size and rows_read/rows_written are measured separately; no daily free-plan guarantee is inferred from short observations. Historical audit remains untouched. Single agent; author tests do not masquerade as independent approval.
