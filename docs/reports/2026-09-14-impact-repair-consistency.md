# Coupled impact repair choices

## Change contract

The existing annotator owns one initial classification and one bounded repair.
The changed boundary is the repair request schema and its immediate decoder:
candidate facts -> allowed identity combinations -> model choice -> canonical
identity fields -> unchanged validator -> append-only assessment. Persisted
schemas, scheduler ownership, credentials and retry budgets do not change.
The model retains semantic choice; the decoder only expands an offered token.
Unrecognized choices, extra contradictory fields, invalid factual differences
and failed public explanations remain rejected. No prose-derived judgment is
accepted. Restart uses existing jobs and main-only forward repair.

A repair chooses one atomic combination of relation, update type and candidate
ID from the request's finite universe. SAME_EVENT choices require eligible
anchors. NEW_EPISODE choices require complete context. Existing validators still
check evidence and factual differences. Initial requests remain unchanged.
The new request contract has a separate repair version so provider evidence is
not confused with the old wire format. No runtime accepts a remote delta or a
new persisted schema; old historical evidence remains audit-only.

Verification must exercise the production request/decoder/validator path,
unknown and inconsistent responses, empty and truncated candidate contexts,
and the real incident's candidate receipt. After exact-head CI and merge, verify
the original job's actual completion and persisted assessment under the new
runtime; provider errors are external availability limits, not success.
